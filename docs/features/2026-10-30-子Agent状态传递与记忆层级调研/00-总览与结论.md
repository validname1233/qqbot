## 一、总结论：我们的做法不偷懒，但停在了一半

**"子 Agent 注册为 tool + 规格书文本"正是当前业界主流且被官方推荐的形态**：

- LangChain 官方多 Agent 指南把这个模式称为 **Subagents**："A main agent
  coordinates subagents as tools. All routing passes through the main agent"，
  且 langgraph-supervisor 库的 README 明确写着"我们现在推荐**直接用 tools 实现
  supervisor 模式**而非本库"——工具调用路线是官方收敛后的答案；
- Claude Code 的 Task/Agent 工具就是同一形态的产品级实现：主模型发一个 tool
  call、参数是它自己写的任务描述、子 Agent 在全新上下文里跑、返回报告；
- Anthropic 多 Agent 研究系统的 lead→subagent 传递**本质上也是一份写得很讲究
  的规格书**（"objective + output format + tool guidance + task boundaries"
  四字段配方）；
- 学理上，NLIP（Ecma TC56，2025 年标准化）代表的新一代 Agent 通信协议哲学
  就是"自然语言 + 各自内化"而非共享本体的形式化消息——FIPA ACL 那套形式化
  协议"从未获得预期的商业支持"。

**真正"偷懒"的地方在两侧的持久层缺失**（业界都补了，我们没有）：

1. **入侧缺"共享的策划记忆"**：唤起子 Agent 时只传规格书，没有把稳定的小块
   上下文（用户画像/既定事实/会话约定）一起注入——Claude Code 的子 Agent
   虽然不继承对话转录，但**各级 CLAUDE.md 会注入每个子 Agent**；
2. **出侧缺"子 Agent 的转录归档"**：子 Agent 过程目前彻底丢弃（深检连
   process 行都没有），业界的做法是**归档但默认不可见**——Claude Code 存
   `agent-{id}.jsonl`（30 天保留、可 resume、不受主对话压缩影响），DSH 把子
   Agent 转录存为第一公民的独立 Session 日志。

一句话概括业界共识：**上下文隔离、记忆共享、交换蒸馏**。

## 二、四维对比（各方案速查）

| 方案 | 上下文传递保真度 | 子 Agent 隔离性 | 结果回流结构 | token 成本 |
|---|---|---|---|---|
| **我们（tool + 规格书文本）** | 中——取决于主 Agent 写规格书的质量，无校验 | 高——只见规格书 | 弱——自由文本报告 | 低 |
| OpenAI `as_tool`（结构化版） | 中高——input_type schema 校验 | 高 | 强——output_type 结构化 | 低-中 |
| OpenAI `handoff` | 高（默认传全史，可 filter 裁剪） | 低——接管式，不是隔离 | 无回流概念（控制权转移） | 中高 |
| Anthropic orchestrator-worker | 高——规格书四字段配方 + 计划外存 | 高——并行独立上下文 | 强——蒸馏摘要 + 文件引用 | **很高（≈聊天 15 倍）** |
| Claude Code subagent | 中——任务描述 + CLAUDE.md + 最小环境 | 高——全新窗口 + 工具白名单 | 中——报告（过注入扫描）+ agentId 可 resume | 低 |
| LangGraph 共享 state | 高——结构化 channel + reducer | 中——同图共享，schema 裁剪 | 强——状态更新式 | 中 |
| **DSH subagent（源码）** | 高——spawn/fork 双模式 + 策略事件 + 结构化结果 | 高——独立 Session 日志 | **强——settlement 消息 + send_message 双向 + catalog 发现** | 低-中 |
| FIPA ACL（理论） | 理论高——performative 形式化 | 高 | 形式化 | N/A（失败的标准） |
| Blackboard（理论） | 高——共享工作区 | 中 | 天然结构化 | N/A（大载荷传引用） |

## 三、对我们架构的直接判定

| 我们的现状 | 业界对照 | 判定 |
|---|---|---|
| 子 Agent = tool，规格书文本唤起 | Claude Code / LangChain 官方推荐 | ✅ 保留 |
| 规格书是单字段自由文本 | Anthropic 四字段配方 / OpenAI input_type / LangGraph task_description channel | ⚠️ 可升级为结构化 |
| 子过程丢弃（深检零 process 行） | Claude Code agent-{id}.jsonl / DSH 独立 Session | ❌ 应归档（已列入深检子 Agent 化方案） |
| 报告自由文本回流 | DSH structured result / Anthropic 蒸馏 + 文件引用 | ⚠️ 报告可控长度，暂够用 |
| 无子 Agent 独立记忆 | Claude Code agent-memory / Letta 私有 block / LangGraph namespace | ❌ 深检/工作台暂无需求，M4 一起设计 |
| 借用父闸（深检方案） | DSH authority 两级中断（user/parent） | ✅ 方向一致 |

## 四、后续行动映射（与已有计划的衔接）

1. **深检子 Agent 化**（方案已定）：本次调研确认其四条要点全部踩在业界主线上；
   补充建议——工具描述按 Anthropic 四字段配方改写（目标/输出格式/工具指引/
   任务边界），比单段描述更能引导主模型写出高质量委派；
2. **深检 process 行落库**：与 DSH 的"子 Agent 独立 Session 日志"同构（我们的
   简化版：共用主事件流 + origin 标记，而非独立日志文件）；
3. **M4 长期记忆**：`03-记忆层级持久化.md` 的结论可直接作为设计输入——业界
   共识是"同一持久层 + 命名空间划分归属"，我们的单表 conversation_events
   可以继续做唯一事实源（加作用域列），不必另起存储；
4. **观察项**（暂不做）：子 Agent resume（DSH/Claude Code 都支持，我们的一次性
   规格书暂无续问需求）；报告注入扫描（Claude Code 对子报告做注入检测——QQ
   群聊内容不可信，若未来子 Agent 处理外部网页内容，值得抄这条）。
