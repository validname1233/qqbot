# 框架与理论：主/子 Agent 状态传递的成熟模式

> 2026-10-30。子 Agent 网络调研产出（官方文档实抓，URL 随文）。
> 姊妹篇：02-DSH源码专篇（源码级）、03-记忆层级持久化。

## 0. 核心疑问的直接回答

**"子 Agent 注册为 tool + 规格书文本"不是偷懒，是业界主流**：

- LangChain 官方多 Agent 指南称此模式为 **Subagents**："A main agent
  coordinates subagents as tools. All routing passes through the main agent"；
  且官方明确 **"Subagents work in isolation with only their relevant context
  (low token usage)"、"Subagents are stateless by design"**；
- langgraph-supervisor 库 README 顶部声明："We now recommend using the
  **supervisor pattern directly via tools** rather than this library"——
  工具调用路线是框架厂商收敛后的答案；
- 真正可以改进的是三个工程细节：**规格书结构化、上下文可选注入、结果结构
  化回流**。

## 1. OpenAI Agents SDK：handoff vs as_tool 的本质分界

**handoff = 控制权转移**："it's as though the new agent takes over the
conversation, and gets to see the entire previous conversation history"——
接手方默认看到全量历史；执行层面"If the LLM requests a handoff, we update
the current agent and input, and re-run the loop"（主 Agent 被替换）。
`input_filter` 可裁剪交接历史（HandoffInputData → 新 HandoffInputData），
官方提供 `remove_all_tools`（移除历史中工具条目）与实验性
`nest_handoff_history`（压缩为有序摘要段）。

**as_tool = 不转移的委托**（= 我们的形态）：文档明确建议"If you want
structured input for a nested specialist without transferring the
conversation, prefer `Agent.as_tool`"。改进位：`input_type`（Pydantic schema
本地校验规格书）、`output_type`（强制结构化结果）。

**本地上下文 vs LLM 上下文的关键区分**（context 文档页）：RunContextWrapper
（依赖注入的 app state）"is not sent to the LLM"；"When an LLM is called,
the only data it can see is from the conversation history"——想让子 Agent
知道什么，必须显式放进历史/规格书，没有隐式共享。

URL: https://openai.github.io/openai-agents-python/handoffs/ 、/running_agents/ 、/context/

## 2. Anthropic 多 Agent 研究系统（orchestrator-worker）

正确 URL：https://www.anthropic.com/engineering/multi-agent-research-system

- **任务传递 = 讲究的规格书**："Each subagent needs an objective, an output
  format, guidance on the tools and sources to use, and clear task
  boundaries."（四字段配方）；反面教训："Without detailed task descriptions,
  agents duplicate work, leave gaps, or fail to find necessary information."
- **计划外存抗截断**：lead agent "saves its plan to Memory (to survive
  context truncation)"——重要状态不只靠上下文；
- **回流 = 蒸馏**：subagent "condensing the most important tokens for the
  lead research agent"；**大工件写文件系统只回传轻量引用**（对抗传话游戏）；
- **关键数据**：单 Agent ≈ 聊天的 4 倍 token，多 Agent ≈ 15 倍；
  "token usage by itself explains 80% of the variance"（BrowseComp）；
  收益：多 Agent 比单 Agent 内部评测高 90.2%（广度型问题）；
  并行 3-5 subagent + 各 3+ 并行工具调用，研究时间最多缩短 90%；
- 工程哲学："Agent-tool interfaces are as critical as human-computer
  interfaces"——自动重写工具描述的 agent 把任务完成时间缩短 40%。

## 3. Claude Code 的 subagent（Task/Agent 工具）

URL: https://code.claude.com/docs/en/sub-agents

- **子 Agent 上下文 = 专属 system prompt（agent 文件正文）+ 主 Agent 写的
  委派消息 + 基础环境信息**（工作目录、各级 CLAUDE.md、git 快照）——
  "Each subagent starts with a fresh, isolated context window"，拿不到主
  Claude Code 的 system prompt，**也不继承对话转录**；
- **fork 例外**："The exception is a fork, which inherits the parent
  conversation instead of starting fresh"——需要全史时有逃生舱；
- **回流**：前台阻塞至完成返回 final report；后台 subagent 的结果"reach
  Claude as a completion notification in a later turn"。**回流前做注入扫描**：
  "Claude Code scans each subagent's final report before Claude reads it"
  （不改动内容，检测注入式指令）；
- **resume**：完成的 subagent 返回 agent ID，主 Agent 可带完整历史续问；
- **定义**：YAML frontmatter（name/description/tools/model/permissionMode/
  maxTurns/isolation）+ Markdown system prompt。

## 4. LangGraph：共享 state vs 消息传递

**共享 state（channels + reducers）**：图状态 = "A shared data structure
that represents the current snapshot"；节点返回部分更新，"Each key in the
State has its own independent reducer function"；`add_messages` 按 message ID
追加/更新。主/子是图上节点，**没有规格书，子节点直接读共享 state 的字段**。

**supervisor（消息传递）**：langgraph-supervisor 的 handoff tool 默认传
"full message history (all of the messages generated in the supervisor up
to this point)"；可定制 `task_description` 参数（"Detailed description of
what the next agent should do, including all of the relevant context."）；
`output_mode`: full_history vs last_message；`create_forward_message_tool`
把 worker 末条消息原样透传（"avoids potential misrepresentation of the
worker's response through paraphrasing"——防转述失真）。

URL: https://github.com/langchain-ai/langgraph-supervisor 、
https://docs.langchain.com/oss/python/langgraph/ 、/multi-agent

## 5. 学术理论脉络（简）

- **FIPA ACL / speech act**（Searle 1960s → FIPA 1996 → IEEE 2005）：通信
  建模为言语行为（inform/request/propose…），performative + 共享本体编码
  内容。历史评价："never succeeded in gaining the commercial support which
  was originally envisaged"——形式化协议在商业上失败；
- **NLIP**（Ecma TC56，2025 年 12 月成标准）："do not require a shared
  ontology among communicating agents… use generative AI models to translate
  natural language text into a local ontology"——**新一代协议回归自然语言
  传递 + 各自内化**，正是 LLM 多 Agent 用规格书的学理注脚；
- **Blackboard**（Hearsay-II，1970s）：结构化全局工作区 + 知识源观察写入 +
  控制组件调度——LangGraph 共享 state 是其现代版；Anthropic 的"文件系统
  工件 + 引用回流"也是 blackboard 思想；
- **经典争论**：直接消息传递（低耦合、需协议、适合异构开放系统）vs 共享
  记忆（异步解耦、适合紧耦合协作）——现代框架两边都占：规格书 = 消息，
  state/文件系统 = 黑板。

URL: https://en.wikipedia.org/wiki/Agent_Communications_Language 、
/wiki/Blackboard_(design_pattern)

## 6. 对我们项目的七条建议（调研 Agent 原文归纳）

1. 保留 tool 调用架构（与 Claude Code/Anthropic/LangChain 官方一致）；
2. 规格书升级为结构化 schema（目标/输出格式/工具指引/边界四字段起步）；
3. 回流改"结构化 + 大载荷落盘传引用"（`{summary, artifacts, status}`）；
4. 可选：规格书加一节"从主对话抽取的相关背景"（对应 handoff 裁剪思想）；
5. 回流报告做注入扫描（QQ 群聊内容不可信，这条对我们尤其相关）；
6. 支持 agentId/resume（主 Agent 可带上下文追问子 Agent）；
7. 成本意识：多 Agent ≈15 倍 token，只对高价值任务启用。
