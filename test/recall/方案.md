# 长期记忆召回准确率测试方案

## 1. 目标与范围

对长期记忆的混合检索（向量 RAG + 关键词 BM25 + RRF 融合）做**准确率评测**，回答三个问题：

1. 单 RAG、单关键词、RRF 混合三种召回模式，在我们真实数据形态下的准确率各是多少？
2. RRF 的参数（`rrfK`、通道权重）怎么调最优？
3. 语料从 30 条扩到 100 条后，召回质量有没有退化？

明确不在范围内：性能压测（已有「面试/分词入库性能对比」）、生产库数据（测试用独立数据库文件，与线上 `data/memory.sqlite` 完全隔离）。

## 2. 总体架构：测「生产正在跑的那份代码」

测试不复制实现，而是**复用生产代码**：把 `src/agent/memory/long-term.ts` 的召回逻辑抽成一个可参数化的导出函数 `hybridRecall(key, queryText, params, precomputedEmbedding?)`，生产的 `search()` 内部也改调它。测试脚本 import 同一个函数——保证测出来的数字就是线上行为的数字，不会出现「快照代码和生产代码漂移」。

**数据库隔离**：`config.ts` 新增 `memoryDbFile`（环境变量 `MEMORY_DB_PATH`，默认 `memory.sqlite`，落在 `data/` 下）。测试跑时设 `MEMORY_DB_PATH=recall-test.sqlite`，得到独立库文件，重置 = 删文件。

**Embedding 用真接口**（智谱）：约 100（灌库）+ 30（查询）次调用，成本几分钱。假向量会让向量通道变成随机噪声，测出的准确率无意义。同一 query 的 embedding 在多模式间**复用同一次计算**（`precomputedEmbedding` 参数），保证模式间对比公平。

**不依赖 QQ 事件链路**：存储层 API 本来就是 `(key, content, ...)` 纯参数，脚本直接调用，webhook/handler 不会被打扰。

## 3. 目录结构

```
test/recall/
  方案.md            本文档
  config.json        测试配置（模式、权重、RRF/BM25 参数、topK）
  run.sh             一键入口（seed / test / reset / all）
  seed.ts            灌库：corpus.json → 测试库
  eval.ts            评测：跑全部 query → 指标报表
  data/
    corpus.json      100 条测试记忆（内容可整体替换）
    queries.json     查询集 + gold 标注
```

运行产物：`data/recall-test.sqlite`（已在 .gitignore 的 `data/` 内，不会误提交）。

## 4. 测试数据格式

### corpus.json —— 记忆语料

```json
[
  { "id": "M001", "content": "用户对花生严重过敏，绝对不能吃花生和花生酱", "memory_index": "花生过敏" },
  { "id": "M002", "content": "…", "memory_index": "…" }
]
```

| 字段 | 说明 |
|---|---|
| `id` | 语料内稳定标识（M001~M100），gold 标注引用它。**不用数据库行 id**——清库重灌后行 id 会变，content 唯一性保证 id 可恢复映射 |
| `content` | 记忆正文，评测的检索对象 |
| `memory_index` | 摘要（灌库必填字段，测试里直接给，不走 LLM 生成，保证确定性） |

现有语料为 100 条虚构「用户记忆」，覆盖家人朋友、饮食健康、工作学习、游戏娱乐、数字账号等类别，刻意包含：字面易命中的（专名/数字/ID）、需要语义改写的（「不能喝牛奶」vs「乳糖不耐受」）、互为干扰项的相似记忆。**内容可整体替换**，换数据不改代码。

### queries.json —— 查询集

```json
[
  { "query": "我对什么食物过敏？", "gold": ["M006", "M011", "M099"] },
  { "query": "我的B站ID是什么？", "gold": ["M053"] }
]
```

查询分三类，各占一定比例：

- **字面型**（关键词通道应强）：问 ID、数字、专名，如「工号是多少」「近视多少度」；
- **语义型**（向量通道应强）：换说法问，如「我为什么不能喝牛奶」（记忆原文是「乳糖不耐受」）；
- **宽泛/多 gold 型**：一条 query 对应多条相关记忆，如「我养过什么宠物」→ 猫 + 仓鼠两条。

## 5. 模式与参数：config.json

```json
{
  "dbKey": "test:recall",
  "corpusFile": "data/corpus.json",
  "queriesFile": "data/queries.json",
  "modes": ["rag", "keyword", "hybrid"],
  "topK": 5,
  "minSimilarity": 0.35,
  "rrfK": 60,
  "vecWeight": 1.0,
  "kwWeight": 1.0,
  "bm25K1": 1.5,
  "bm25B": 0.75
}
```

**模式语义**（关键设计：退化必须「既不贡献分数、也不贡献候选」）：

| mode | vecWeight | kwWeight | 效果 |
|---|---|---|---|
| `rag` | 1 | 0 | 纯向量召回：关键词通道完全跳过（不参与打分也不进候选池） |
| `keyword` | 0 | 1 | 纯 BM25 召回：向量通道完全跳过（连 embedding 调用都省掉） |
| `hybrid` | config 值 | config 值 | 加权 RRF：`score = Σ wᵢ/(rrfK + rankᵢ)`，默认 1:1 等于生产行为 |

调参实验做法：改 `modes` 只留 `["hybrid"]`，再调 `vecWeight`/`kwWeight`（如 0.7/0.3）、`rrfK`（30/120）、`minSimilarity`（0.25/0.45）等，重跑 `test` 对比指标。`modes` 里的多个模式会在**同一次运行、同一批 embedding** 下依次评测并打印对比表。

## 6. 评测指标

| 指标 | 定义 | 看什么 |
|---|---|---|
| **Recall@topK** | `|gold ∩ topK 结果| / |gold|`，按 query 求平均 | 主指标：该召回的召回了没有 |
| **MRR@topK** | 第一条命中 gold 的排名倒数（无命中记 0），按 query 求平均 | 排序质量：第一条正确结果排得多靠前 |
| 命中分布 | 每模式全对 / 部分 / 全 miss 的 query 数 | 定位失败模式（哪类查询拉垮） |

结果按模式打印对比表；`--verbose` 额外逐条打印 query、gold、各模式召回的语料 id，便于定位单条 badcase。

## 7. 使用流程（run.sh，Git Bash）

```bash
cd qq-bot/test/recall
./run.sh all      # 清库 → 灌 100 条（约 1 分钟，含真实 embedding 调用）→ 全模式评测
./run.sh seed     # 只灌库（已灌则跳过；--force 强制重灌）
./run.sh test     # 只评测（读 config.json）
./run.sh reset    # 删测试库文件
```

run.sh 做的事：cd 到项目根 → `export MEMORY_DB_PATH=recall-test.sqlite` → `npx tsx --env-file=.env test/recall/xxx.ts`。`.env` 提供全部必填变量（含 `EMBEDDING_API_KEY`）；`MEMORY_DB_PATH` 是进程内 export 的，与 `.env` 无键冲突。

## 8. 结果解读框架

- **hybrid 应 ≥ max(rag, keyword)**：若某一模式反而更好，先看失败 query 属于哪类（字面型/语义型），通常是权重或 `minSimilarity` 不合适；
- **rag 明显弱** → 查 `minSimilarity` 是否过严、embedding 对口语化 query 的适配；
- **keyword 明显弱** → 查分词质量（ICU 对专名的切分）、停用词表；
- **换 corpus 后重跑**：语料替换后 gold 重标即可，代码零改动。

## 9. 已知边界

- gold 标注有主观性（「宠物」算不算猫粮那条？）——标注口径：只标「直接回答该问题必需的记忆」，相关但非必需的不进 gold；
- 每次重灌库 embedding 会重新调用 API，结果有微小非确定性（同一文本的向量基本稳定，但非逐位相同），模式间对比因复用同一批 embedding 不受影响；
- 生产 `search()` 行为本方案不动（默认权重 1:1），只有抽取重构没有行为变更。
