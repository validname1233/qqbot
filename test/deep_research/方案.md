# 深度检索 A 档实现方案：本地走通「Tavily 起点 + 多轮 open_page + Playwright 交互」

> 状态：实现方案（对应总设计 `docs/superpowers/specs/2026-08-24-deep-web-browsing-design.md` 的二期 A 档）
> 目标：在本地（不接 QQ）跑通深检图全流程：Tavily 起点 → fetch+cheerio 阅读 → Playwright 交互（图级生命周期）→ 汇总报告
> 日期：2026-08-25

## 0. 本方案的范围与坐标

总设计的三期路线里，A 档是"一次深检请求一套浏览器"的最小实现。本方案把它落到文件级：

- **能力层**（browse/ 四件套）：fetch 守卫、cheerio 提取、页面池、Playwright 图级生命周期；
- **编排层**（deep-search 图）：searchNode → browseLlm ⇄ browseTools → synthesize；
- **测试**：test/deep_research/run-graph.ts 直接 invoke 图，全程不碰 QQ 事件层。

与总设计的差异声明：总设计一期的 open_page 只有 fetch+cheerio，Playwright 是二期。本方案把两者合并交付（A 档本来就是二期的内容），但 `open_page`（静态阅读）与 `interact_page`（动态交互）仍是两个独立工具，可以分两步实现、分两步验证。

## 3. 能力层设计

### 3.1 fetch.ts —— 安全抓取

`fetchPage(url): Promise<{ html: string; finalUrl: string }>`。原生 fetch + AbortController（超时 `BROWSE_PAGE_TIMEOUT_MS`）。守卫按总设计 §6.2：

- 协议白名单 http/https；
- DNS 解析后校验全部 A/AAAA 记录非私网（`node:dns` 的 `lookup` with `all: true`，私网段判断手写 IPv4 + ::1/IPv6 ULA）；
- 手动重定向循环（`redirect: "manual"`），≤5 跳，每跳重新过守卫；
- Content-Length 预检 + 流式读计数，上限 2MB；
- Content-Type 必须 text/html（charset 解析取 `<meta charset>` 或默认 utf-8）；
- UA：`qq-bot/1.0 (+web-browse)`。

同域串行：模块级 `Map<host, Promise>` 队列，同一 host 的请求排队且间隔 ≥500ms（进程级，跨会话生效，防打爆小站）。

### 3.2 extract.ts —— cheerio 提取

`extractPage(html, baseUrl): { title, text, links: Array<{ no, text, url }> }`：

- `cheerio.load(html)`，剥 `script/style/nav/footer/aside/header` 后取 `body` 文本（启发式：文本密度最高的子块，简化版可以直接取 body 全文本压空行）；
- 链接：`a[href]` → `new URL(href, baseUrl)` 转绝对 → 过滤 `javascript:`/`mailto:`/同页锚点 → 限 `BROWSE_MAX_LINKS` 条，正文区域内优先；
- 正文按字符截断（≈token 上限 `BROWSE_MAX_CONTENT_TOKENS`，中文 1 字≈1 token）。

### 3.3 page-pool.ts —— 人粒度快照池

内存 `Map<key, { pages: PageSnapshot[]; lastActive: number }>`，key 用 `sessionKey(event)`（人粒度）。存最近 8 页的 `{ url, title, text, links }`，TTL 10 分钟。`open_page` 的 `link` 编号在这里查最近一页的链接表。与浏览器无关——是 fetch 层的"最近浏览记忆"。

### 3.4 browser.ts —— A 档核心：图级生命周期 + 动作串行

```ts
// 对外接口（三档通用，升 B/C 档不改调用方）：
export async function withPage<T>(fn: (page: Page) => Promise<T>): Promise<T>;
export async function releaseBrowser(): Promise<void>;
```

A 档实现：

```ts
let browser: Browser | null = null;
let page: Page | null = null;
let chain: Promise<unknown> = Promise.resolve();   // 动作串行化队列

export async function withPage<T>(fn: (page: Page) => Promise<T>): Promise<T> {
  const run = chain.then(async () => {
    browser ??= await chromium.launch();           // 懒启动
    if (page === null || page.isClosed()) page = await browser.newPage();
    return fn(page);
  });
  chain = run.catch(() => {});                     // 失败不断链
  return run;
}

export async function releaseBrowser(): Promise<void> {
  await chain;
  await browser?.close();                          // 图收尾调用：整个关掉，状态归零
  browser = null; page = null;
}
```

要点：

- **串行化**：深检图 browseTools 节点并发执行同轮多个 tool_calls，所有 interact_page 动作经 `chain` 排队，同一时刻只操作一个 page——总设计 §5.6 A 档的硬要求；
- **图级收尾**：deep-search 图的 synthesize 完成后（`finally` 中）调 `releaseBrowser()`，一次请求一套浏览器，请求结束状态清零、内存归零；
- 每次 `goto` 后带 `page.waitForLoadState("domcontentloaded")`，动作后返回当前 URL 让模型知道"我在哪"。

## 4. 工具层（只挂深检图，不进 agent/registry.ts 共享注册表）

### 4.1 open_page（静态）

参数：`{ url?: string, link?: number }` 二选一。流程：解析目标 URL（link → 查 page-pool 最近快照）→ `fetchPage` → `extractPage` → 快照入池 → 返回总设计 §3.3 的文本格式（标题+正文+编号链接表）。错误细粒度文案（"链接编号已失效，请重新 open_page"）让模型能自愈。

### 4.2 interact_page（动态）

参数：`{ url, action: "click"|"fill"|"scroll"|"screenshot", target?: string, value?: string }`。流程：`withPage(page => page.goto(url) → 动作)`：

- `target` 翻译成 `getByRole` 语义定位（`"button:下一页"` → `page.getByRole("button", { name: "下一页" })`；`"input:搜索"` → `getByPlaceholder`/`getByRole("textbox")`）；
- 动作后 `page.content()` 拿渲染后 HTML → **复用 extract.ts** 提取（动态页面和静态页面共用同一套提取逻辑，这是分层的红利）；
- 返回：`[页面] 标题（当前URL）\n[正文] …\n[链接] …`，格式与 open_page 一致；
- `screenshot`：截图存 `data/deep-research/` 返回路径文本（A 档先不接识图链路，占位说明"截图已保存：<path>"，视觉兜底等 B/C 档再接）。

## 5. 编排层：deep-search 图（src/agent/deep-search.ts）

仿 `agent/loop.ts` 的写法（StateSchema + ReducedValue + 条件边），节点四个：

```text
searchNode → browseLlm ⇄ browseTools → synthesize → END
```

| 节点 | 职责 | 模型 |
|---|---|---|
| searchNode | `tavilySearch(question)`；参数是 URL 则跳过；拼首条 user 消息（问题+起点列表），设 deadline | 无（确定性） |
| browseLlm | `callModel(messages, [open_page+interact_page schema], config.aiModel, false, "browseLlm")` | flash |
| browseTools | 解析 tool_calls、执行（open_page 可并发；interact_page 经 chain 自动串行）、tool 消息拼回、turnCount+1 | 无 |
| synthesize | 仿 synthesizeFinalReply 两条消息模式：system=deep_report（带人设），user=问题+起点+全部浏览记录 | pro + thinking |

State：`question / ctx / messages（ReducedValue）/ turnCount / deadline / report`。

路由条件边（对齐总设计 §5.2）：

- browseLlm 后：无 tool_calls → synthesize；有 tool_calls 且 `turnCount < BROWSE_MAX_TURNS` 且 `now < deadline` → browseTools；否则 → synthesize（预算耗尽优雅降级）；
- browseTools 后：`now < deadline` 且 `turnCount < BROWSE_MAX_TURNS` → browseLlm；否则 → synthesize。

**收尾钩子**：`runDeepSearch()` 用 try/finally 包 `graph.invoke()`，finally 调 `releaseBrowser()`——A 档"图级生命周期"的落点。

**记忆策略**（总设计 §3.5，2026-08-26 修订三确认）：图结束后落「问题 + 报告」两条进短期记忆（`memoryKey` 粒度）——user = 问题原文（带说话人前缀）、assistant = 最终报告；全部中间消息（plan/思维链/tool 结果）都不落库。实现已是这个口径。

> 2026-08-26 总设计另有修订二/三（plan & execute：planNode + 思维链双职责产生机制）尚未同步实现——图结构以总设计 §5.2 为准，本文件记录的是 A 档已实现的四节点版本。

## 7. 测试脚本：test/deep_research/run-graph.ts

仿 `test/recall/eval.ts` 的组织方式（tsx 直跑 + `--env-file=.env`），**直接 invoke 图，不碰 QQ 事件层**：

```ts
// test/deep_research/run-graph.ts —— 本地直跑深检图（A 档验证）。
// 用法：npx tsx --env-file=.env test/deep_research/run-graph.ts "调研问题" [--verbose]
//   --verbose 会把每轮 browseLlm 的 tool_calls 和每页标题打出来。
import { runDeepSearch } from "../../src/agent/deep-search.js";

const question = process.argv[2];
if (!question) {
  console.log("用法：npx tsx --env-file=.env test/deep_research/run-graph.ts \"调研问题\" [--verbose]");
  process.exit(1);
}
const verbose = process.argv.includes("--verbose");

console.log(`[run-graph] 问题：${question}`);
const t0 = Date.now();
const report = await runDeepSearchLocally(question);   // 见下方说明
console.log(`\n[run-graph] 耗时 ${((Date.now() - t0) / 1000).toFixed(1)}s\n`);
console.log("===== 最终报告 =====\n");
console.log(report);
process.exit(0);   // 显式退出：Playwright/SQLite 句柄不让进程自然结束
```

两个适配点：

1. **`runDeepSearchLocally`**：`runDeepSearch(question, ctx)` 的 ctx 是 `MessageContext`（要 event 才能取 memoryKey/getSystemPrompt）。给 deep-search.ts 加一个测试导出——`runDeepSearchLocally(question)`，内部构造 mock ctx（`memoryKey` 固定 `"test:local"`、`getSystemPrompt` 用默认人格分支），跳过短期记忆落库（测试库会污染生产 memory.sqlite，本地验证用不着记忆写入）。生产入口 `runDeepSearch` 照常走完整路径；
2. **`process.exit(0)`**：Playwright 进程和 better-sqlite3 句柄会挂住事件循环，显式退出防止脚本"跑完不结束"。

可选加 run.sh（仿 recall/run.sh），A 档验证用直接命令行足够，不强制。
