## 二、30 次选择失败的四类归因

### ① 死金标（12 次）——装置问题，非模型失败

multi-tool-001 / 004 / 005、hidden-param-002 四个场景的金标路径含
**已删除的 add_memory 工具**（输入特征："帮我记一下""记住我怕辣"）。
模型不可能调用不存在的工具，12 次全败是必然。

**教训**：首次清理只按 category 删了 19 个死场景，漏掉了藏在
multi_tool/hidden_param 类别里、金标路径引用 add_memory 的 4 个。
**已在本次修正**：
- multi-tool-001/004/005（复合指令）：金标保留真实工具意图
  （set_reminder / open_page / search），仅剔除 add_memory 步；
- hidden-param-002（纯记忆请求）：金标改为 no_tool 语义——无记忆工具时
  正确行为是不调用任何工具、口头回应（考察不幻觉调用）。
**修正后复跑**（reports/agent-eval-live-2026-10-30T05-31-26，12 次）：
7 过 5 败——multi-tool-004、hidden-param-002 全过；残余失败是真行为
分歧（见④'记忆代偿'与②get_time 家族）。
**剔除死金标后的有效选择准确率 = 225/243 ≈ 92.6%**（修正后口径）。

### ② get_time 前置规则与旧金标的冲突（约 12 次）——金标过时，模型多数在服从 M2.2

特征：模型在 search/set_reminder 前多调了一次 get_time，金标（提示词 v2
之前写的）只期望单工具。典型案例 multi-tool-003（"**最近**有什么新电影，
再查查**周末**带娃去哪"）：M2.2 明文规定相对时间必须先取 get_time——
**模型在服从我们自己的新规则，旧金标没跟上**。3 次采样行为完全一致
（确定性服从），说明不是随机抖动。

处置建议：这类场景金标应补 get_time 路径（与 M2.2 对齐），属装置维护，
下一轮修正。其中 context-005 r3（生成 2×get_time、始终没调 search）是
该家族里唯一的能力型失败。

### ③ 漏调 get_time（2 次）——真实规则违反

two-turn-007（"**明晚**九点提醒我"）两次采样直接 set_reminder、跳过
get_time，违反 M2.2。与②同源互为镜像：规则在"该调"场合偶有漏调，
在"可调可不调"场合偏多调。M2.2 措辞的精确度是真机打磨项（二期清单）。

### ④ 重复调用与 URL 构造（4 次）——零散能力项

- set-reminder-011 r1/r2：把"吃完饭隔一会儿再吃胃药"的闲聊补充读成了
  第二个提醒请求（set_reminder×2，金标 1 次）——指代理解偏差；
- search-007/010 若干：同 query 的 search 连发两次——纯浪费型 precision 损耗；
- open-page-008 r2/r3（"打开百度百科查量子纠缠"，金标=search）：
  3 次里 2 次零调用直接作答——无显式 URL 时模型不总是能想到"先搜入口"。

### ④' 记忆代偿（复跑新发现）——行为设计题，非缺陷

修复金标后复跑暴露：**没有记忆工具时，模型会创造性代偿**——
multi-tool-005（"记一下我下周四要去上海出差"）3 次采样中 1 次把"记一下"
转化为 `set_reminder(7 天后提醒出差)`，r2/r3 则直接口头确认"记下了"
（口头承诺当前架构兑现不了——没有持久化）。这是 M4 长期记忆落地前的
真空期行为：**真机风险点**——用户以为 bot 记住了，下一轮 v7 投影里没有
这句话（说过的才进 L1，"记下了"的承诺本体在，被记的事实不在）。
观察项：M4 落地前，提示词层是否值得加一句"没有记忆工具时明确告知记不住"
（诚实路线）——交给真机表现决定。

## 三、结论与下一步

1. **基线成立**：有效选择准确率 92.6%（死金标剔除口径）、零误调用、
   协议层零错误（JSON/schema 100%）。新架构（v9 直通 + 提示词 v2 +
   v10 压缩）的工具判断质量可以作为后续迭代的回归参照；
2. **装置债已还清**：死金标 4 场景修正完毕（复跑验证 7/12 过，残余为真
   行为分歧非装置错误）。剩余装置维护项：get_time 前置场景的金标未与
   M2.2 对齐（约 12 次失败的主因）——修正后预期有效选择准确率 ~97%，
   留给下一轮（与 M2.2 措辞打磨一起做，避免两头改）；
3. **提示词真机打磨候选**（按收益排序）：
   - M2.2 get_time 触发词精确化（"明晚"该触发没触发、"Python 3.13 新特性"
     不必触发却触发——规则两向都有毛边）；
   - 重复调用抑制（同参同工具同轮不重复，search-007/010 型浪费）；
   - 无 URL 的"打开 XX 查 YY"→ search 入口的引导（open-page-008 型）；
   - 记忆真空期行为（④'）：诚实告知 vs 口头承诺，真机观察后定；
   - multi-tool 复合指令的第二意图召回（"顺便记一下"家族，M4 落地后
     自然消解）。
4. **可复跑**：`npx tsx --env-file=.env test/agent_tool_accuracy/e2e.ts
   --mode live --repeat 3`（当前 85 场景版本）。
